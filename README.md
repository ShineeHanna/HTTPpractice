# For_test — сервис коротких ссылок на Go

Идея проекта: принять длинный URL, придумать короткий код, сохранить пару в PostgreSQL и перенаправлять пользователя на исходный URL по этому коду. В проекте уже есть HTTP-маршруты, модель ссылки и подключение к PostgreSQL. Сохранение ссылок, переадресация и полноценная авторизация ещё в разработке.

## Как соединены части проекта

```text
cmd/main.go
  ├─ configs.LoadConfig() → .env и переменные окружения
  ├─ db.NewDb(conf) → GORM + драйвер PostgreSQL → PostgreSQL
  ├─ NewLinkRepositiry(database) → LinkRepository
  └─ http.ServeMux
       ├─ /auth/... → Auth Handler → разбор и проверка JSON
       └─ маршруты ссылок → LinkHandler → LinkRepository
                                            ↓
                                  здесь будут запросы к PostgreSQL

migrations/auto.go → GORM AutoMigrate(&link.Link{}) → схема в PostgreSQL
```

Сервер собирает зависимости один раз при запуске. Затем маршрутизатор по методу и пути HTTP-запроса выбирает обработчик. Обработчик отвечает за HTTP: читает запрос и формирует ответ. Репозиторию отводится работа с записями в базе. Модель `Link` описывает данные одной короткой ссылки, общие для приложения и слоя хранения.

## Почему столько упоминаний `db`

В основном приложении вызов `db.NewDb(conf)` выполняется один раз. `main.go` передаёт полученный указатель репозиторию, а репозиторий хранит этот же указатель в поле `Database`. Передача аргумента и присваивание поля повторно подключение не открывают.

| Имя в коде | Что означает |
| --- | --- |
| `"pack/pkg/db"` / `package db` | Путь импорта и имя пакета проекта. Префикс `pack` взят из `go.mod`. |
| `conf.Db.Dsn` | Строка с параметрами подключения, прочитанная из переменной `DSN`. В ней обычно указаны адрес, порт, имя базы и данные для входа. |
| `db.NewDb(conf)` | Функция из пакета `db`. Передаёт DSN драйверу PostgreSQL, вызывает `gorm.Open` и возвращает `*db.Db`. |
| `*gorm.DB` | Объект GORM, через который код выполняет операции с базой. GORM переводит операции над Go-структурами в SQL. |
| `*db.Db` | Указатель на структуру проекта, в которую встроен `*gorm.DB`. Методы GORM доступны через эту структуру благодаря встраиванию. |
| `db` слева в `db := db.NewDb(conf)` | Локальная переменная в `main()`. В правой части `db` ещё означает пакет. После объявления внутри `main()` это имя обозначает переменную. Имя `database` помогло бы различать эти две роли. |
| `LinkRepository.Database` | Поле, в котором репозиторий хранит полученный объект GORM в обёртке `*db.Db`. Когда заработает сохранение, репозиторий будет выполнять запросы через это поле. |
| `gorm.Model` в `Link` | Готовые поля записи: `ID`, `CreatedAt`, `UpdatedAt`, `DeletedAt`. Они описывают данные строки таблицы. |

Сам **PostgreSQL** — отдельный процесс, который хранит таблицы и выполняет SQL. В этом проекте за запуск PostgreSQL отвечает Docker Compose, а Go-сервер обращается к нему через GORM.

**Миграция выполняется отдельной программой.** У неё своя функция `main()` и свой вызов `gorm.Open`. Она подключается к базе из `DSN`, чтобы создать или обновить таблицы и индексы по модели `Link`. Основной сервер использует эту базу для работы с данными. При запуске сервера миграция автоматически не выполняется.

## Папки и файлы

### Точка входа и конфигурация

| Файл | За что отвечает |
| --- | --- |
| [`cmd/main.go`](cmd/main.go) | Загружает настройки, открывает подключение к БД, создаёт репозиторий, регистрирует маршруты авторизации и ссылок, запускает HTTP-сервер на порту `8080`. Здесь видно, какой объект кому передаётся. |
| [`configs/config.go`](configs/config.go) | Подгружает `.env` и считывает `DSN` в `Config.Db.Dsn`, а `TOKEN` — в `Config.Auth.Secret`. Если при загрузке файла произошла ошибка, продолжает чтение из окружения. |
| `.env` | Локальные значения `DSN` и `TOKEN`. Первый параметр нужен для подключения, второй предназначен для авторизации. Сейчас значение `TOKEN` в обработчиках не используется. Файл исключён из Git. |

### Короткие ссылки — `internal/link/`

| Файл | За что отвечает |
| --- | --- |
| [`handler.go`](internal/link/handler.go) | Регистрирует HTTP-маршруты ссылок. Получает `LinkRepository` из `main.go`. Здесь будет чтение URL из запроса, вызов репозитория и отправка результата клиенту. |
| [`model.go`](internal/link/model.go) | Описывает `Link`: исходный URL, короткий код `Hash` и стандартные поля `gorm.Model`. `NewLink(url)` создаёт объект в памяти и генерирует случайный код из 10 букв. Тег `gorm:"uniqueIndex"` задаёт уникальный индекс для `Hash` при миграции. |
| [`repository.go`](internal/link/repository.go) | Хранит `*db.Db`. `NewLinkRepositiry` только собирает структуру с переданным указателем. Метод `Create(link *Link)` уже объявлен, но его тело пока пустое. Здесь будет запись в таблицу через GORM. |
| [`CREATE DATABASE link;.pgsql`](internal/link/CREATE%20DATABASE%20link%3B.pgsql) | SQL для ручного создания базы с именем `link`. Это одноразовый шаг для локального окружения, если такой базы ещё нет. Таблицу для ссылок затем подготавливает миграция. |

### Авторизация — `internal/auth/`

| Файл | За что отвечает |
| --- | --- |
| [`handler.go`](internal/auth/handler.go) | Регистрирует вход и регистрацию. Оба обработчика читают и проверяют JSON. Вход возвращает тестовый токен, регистрация выводит данные в лог. Проверки пароля, сохранения пользователя и выдачи подписанного токена пока нет. |
| [`payload.go`](internal/auth/payload.go) | Описывает JSON-структуры запросов и ответов. Вход ожидает `email` и `password`, регистрация дополнительно ожидает `name`. Теги `validate` задают обязательность полей и проверку формата email. |

Папка `internal/` хранит код самого приложения. Правило видимости Go ограничивает импорт таких пакетов кодом внутри родительского дерева проекта.

### Общие функции — `pkg/`

| Файл | За что отвечает |
| --- | --- |

| [`pkg/res.go`](pkg/res.go) | Записывает HTTP-статус, заголовок `Content-Type: application/json` и тело JSON-ответа. |

## Что происходит при HTTP-запросе

| Маршрут | Что делает текущий код |
| --- | --- |
| `POST /auth/login` | Читает и проверяет JSON, затем возвращает фиксированный токен. |
| `POST /auth/register` | Читает и проверяет JSON, затем выводит данные в лог. |
| `POST /link/login` | Зарегистрирован как маршрут создания ссылки. Обработчик вызывает `Create()` без аргумента, хотя репозиторий ожидает `*Link`. |
| `PATCH /link/{id}` | Зарегистрирован, тело обработчика пустое. |
| `DELETE /link/{id}` | Достаёт `id` из пути и выводит в лог. |
| `GET /{hash}` | Зарегистрирован для перехода по короткой ссылке, тело обработчика пустое. |

На примере **создания ссылки** полный путь будет таким: обработчик получает URL из тела запроса → `NewLink(url)` создаёт структуру с коротким кодом → репозиторий получает `*Link` и записывает её через GORM → обработчик возвращает результат клиенту. Сейчас из этой цепочки есть генерация кода, подключение к БД и каркас обработчика с репозиторием.

## Как запускать локально

Запускай команды из корня проекта, где находится `go.mod`. Для подключения к PostgreSQL с компьютера укажи в `.env` свой `DSN` с `host=127.0.0.1`, `port=5434` и именем нужной базы. Имя пользователя и пароль должны совпадать с настройками твоего PostgreSQL.

1. Запусти PostgreSQL: `docker compose up -d postgres`.
2. Если в DSN указано `dbname=link` и базы `link` ещё нет, выполни `CREATE DATABASE link;`, подключившись к существующей базе `postgres`.
3. После устранения ошибки сборки выполни `go run ./migrations`, чтобы подготовить таблицу, затем `go run ./cmd`, чтобы запустить HTTP-сервер.

**Текущая проверка.** `go test ./...` останавливается на вызове `Create()` в [`internal/link/handler.go`](internal/link/handler.go#L29). Эта ошибка блокирует и HTTP-сервер, и команду миграции: обе программы импортируют пакет `internal/link`. Файлов `*_test.go` в проекте пока нет.

## В каком порядке продолжить

1. Довести один сценарий от запроса до ответа: метод создания читает и проверяет URL, передаёт `NewLink(url)` в репозиторий, репозиторий сохраняет запись и возвращает ошибку при сбое.
2. Проверить миграцию и сохранение записи в PostgreSQL. Добавить тесты для успешного создания ссылки, неверного URL и ошибки записи.
3. Сделать поиск по короткому коду и перенаправление, затем обновление и удаление.
4. Реализовать хранение пользователей и авторизацию. Убрать вывод паролей в лог до использования обработчиков с реальными данными.
